# Pegasus configuration & metadata

How this tool configures Pegasus Frontend, what it generates, and how to extend
it.

## Where Pegasus keeps config

Depends on how Pegasus was installed (the tool resolves this automatically; you
can override with `pegasus_config_dir`):

| Install | Config directory |
|---|---|
| Flatpak (default) | `~/.var/app/org.pegasus_frontend.Pegasus/config/pegasus-frontend/` |
| Native / AppImage | `~/.config/pegasus-frontend/` |

## What gets written

### 1. `game_dirs.txt`

Pegasus scans the directories listed in `game_dirs.txt` (one absolute path per
line). The tool registers **each system directory** (the folder that contains
the metadata file) — this is the reliable pattern, since each registered
directory carries its own `metadata.pegasus.txt`.

Existing lines you added yourself are preserved; ours are appended if missing.
The file is backed up before modification.

### 2. `metadata.pegasus.txt` (one per system)

Written into each `<rom_root>/<system>/` folder. Example (`snes`):

```
# Generated by pegasus-bazzite-configurator on 2026-…
# System: Super Nintendo Entertainment System   Emulator: retroarch
# RetroArch core: snes9x_libretro (install via RetroArch > Online Updater)
# Edit freely. Re-running deploy.sh backs this up before any overwrite.

collection: Super Nintendo Entertainment System
shortname: snes
extensions: sfc, smc, zip, 7z
launch: flatpak run org.libretro.RetroArch -L "/home/deck/.var/app/org.libretro.RetroArch/config/retroarch/cores/snes9x_libretro.so" "{file.path}"

# Artwork/media: place assets under media/<rom-basename>/
#   e.g. boxFront.png, screenshot.png, logo.png, video.mp4
```

Keys used:

- `collection:` — human-readable system name shown in Pegasus.
- `shortname:` — short id (used for theme assets / matching).
- `extensions:` — comma-separated file extensions Pegasus treats as games.
- `launch:` — the command Pegasus runs. `{file.path}` (and `{file.dir}`,
  `{file.basename}`) are **Pegasus variables** left literal so Pegasus expands
  them at launch. They are always quoted, so paths with spaces are safe.

When Pegasus is a Flatpak, every `launch:` line is prefixed with
`flatpak-spawn --host ` (see [BAZZITE_NOTES.md](BAZZITE_NOTES.md)).

## Pegasus launch variables

| Variable | Expands to |
|---|---|
| `{file.path}` | Full absolute path to the ROM |
| `{file.name}` | Filename with extension |
| `{file.basename}` | Filename without extension |
| `{file.dir}` | Directory containing the ROM |

## Artwork / media

By default place assets under `<system>/media/<rom-basename>/`, e.g.
`snes/media/Chrono Trigger/boxFront.png`. Common asset names: `boxFront.png`,
`screenshot.png`, `logo.png`, `video.mp4`. A `media/` folder is created for each
system. You can extend metadata with explicit per-game asset lines later — see
the [Pegasus metadata docs](https://pegasus-frontend.org/docs/user-guide/meta-files/).

To fetch artwork + richer metadata automatically, run
[`scripts/autoscraper.sh`](../scripts/autoscraper.sh) (Skyscraper via Podman) —
see [docs/SCRAPING.md](SCRAPING.md).

## ROM directory layout

```
<rom_root>/
  snes/
    metadata.pegasus.txt
    media/
    Super Mario World.sfc
  psx/
    metadata.pegasus.txt
    media/
    Final Fantasy VII (Disc 1).chd
```

**No BIOS/ROM/firmware/key files are provided.** Each generated folder includes
a `HOW_TO_ADD_ROMS.txt` reminder listing the supported extensions and emulator.

## Adding a new system

Create `config/systems/<short>.conf`:

```sh
SYS_SHORTNAME="saturn"
SYS_NAME="Sega Saturn"
SYS_DIRNAME="saturn"
SYS_EMULATOR="retroarch"           # an emulator key from the catalog
SYS_EXTENSIONS="cue, chd, iso, m3u"
SYS_RA_CORE="mednafen_saturn"      # libretro core (RetroArch only)
```

Re-run `./scripts/deploy.sh` (with `--force` to regenerate existing systems).
With `systems: auto`, the system is generated automatically if its
`SYS_EMULATOR` is in your selected emulator list.

## Overriding a system's emulator (without editing .conf)

Use the `system_emulators` config key to point a system at a different installed
emulator at deploy time — no `.conf` edit needed:

```yaml
emulators: retroarch, dolphin
system_emulators: psx=retroarch:swanstation, n64=retroarch:mupen64plus_next
```

Format is `shortname=emulator[:core]`; the `:core` part applies to RetroArch.
A system whose *effective* emulator is in your `emulators` list is auto-included
(so the example above generates `psx` via RetroArch even though DuckStation is
not selected). This is the clean way to use the documented DuckStation →
SwanStation fallback. Overrides are validated: unknown system/emulator, or a
RetroArch override with no core, fails fast.

## Editing generated metadata

The files are plain text and meant to be edited. To regenerate from scratch, run
with `--force` (your current files are backed up first). To keep your edits, run
in the default `install-missing` mode — existing metadata is left untouched.

## Validating

`./scripts/validate.sh` checks that metadata files exist, parse (have
`collection`/`launch`/`extensions`), and have balanced quotes in the launch line,
in addition to checking installs and sandbox permissions.
